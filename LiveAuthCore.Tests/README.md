# LiveAuthCore.Tests

Integration and unit tests for the LiveAuth API.

## Setup

The test project uses:
- **xUnit** for test framework
- **Microsoft.AspNetCore.Mvc.Testing** for integration tests
- **Entity Framework InMemory** database for isolated testing
- **Moq** for mocking services (when needed)

## Running Tests

### From Command Line

```bash
# Run all tests
dotnet test

# Run with detailed output
dotnet test --logger "console;verbosity=detailed"

# Run specific test class
dotnet test --filter "FullyQualifiedName~HealthControllerTests"

# Run with code coverage
dotnet test /p:CollectCoverage=true /p:CoverletOutputFormat=opencover
```

### From Visual Studio / Rider

- Open Test Explorer
- Click "Run All" or run individual tests

## Writing Tests

### Integration Test Pattern

```csharp
public class MyControllerTests : IClassFixture<LiveAuthWebApplicationFactory>
{
    private readonly HttpClient _client;
    
    public MyControllerTests(LiveAuthWebApplicationFactory factory)
    {
        _client = factory.CreateClient();
    }

    [Fact]
    public async Task MyEndpoint_HappyPath_ReturnsOk()
    {
        // Arrange
        var request = new { /* ... */ };
        
        // Act
        var response = await _client.PostAsJsonAsync("/api/my-endpoint", request);
        
        // Assert
        Assert.Equal(HttpStatusCode.OK, response.StatusCode);
    }
}
```

## Notes

- In-memory database is cleared between test runs
- No external dependencies (Lightning, Postgres) needed for tests
- PoW solving tests use low difficulty (faster execution)
- Webhook tests can mock external HTTP calls

## Adding More Tests

1. Create new test class in `Controllers/` or `Services/`
2. Inherit from `IClassFixture<LiveAuthWebApplicationFactory>` for integration tests
3. Add `[Fact]` or `[Theory]` attributes
4. Follow Arrange-Act-Assert pattern
5. Run `dotnet test` to verify
